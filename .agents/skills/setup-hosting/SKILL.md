Read `hosting/handover.json` and the organisation's local `place-record.json`
if one exists. Use the sibling `host-fit/SKILL.md` and its script for questions,
fit reports, suggestions and recording. Locate the sibling beside this skill
in the installed kit, including when loaded through a plugin. Use its command
prefix for that install route from the project root; never use `cd`. Ask at
most the three returned questions in plain words. Keep temporary answers at
the path and with the cleanup described in host-fit. Explain the not-sure
response as the script directs.
Do not ask about residency or ask about long work when the handover supplies
its duration.

Show every fit line and the suggestion with its trade-off and proof status.
The proven menu is empty today. Let the person choose, including keeping an
existing place. Follow host-fit's warn-once rule for a shortfall and record
accepted shortfalls with the person's words and date. Write only the local
place record using `record`; preserve existing infrastructure fields. When
there is no private place repository yet, save the choice-only
`place-record.json` locally as a draft for that repository and tell the person
where it is. This records a preference, not approval to create infrastructure.
Do not create a repository, contact a provider or change the handover.

After recording, say plainly: "Creating the place is not built yet. Nothing
has been created on a host." Stop there. Adoption, provisioning, access,
backups and alerts remain unbuilt. Checking an existing place belongs to
`/check-live`.
